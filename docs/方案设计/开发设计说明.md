# RustFS 离线运输盘同步：开发架构与功能清单

## 1. 系统要解决什么

多个边缘端各自运行 RustFS。边缘端将本地对象写入运输硬盘；硬盘送达中控端后，中控端将对象归档到唯一的中控 RustFS。

```text
边缘端 RustFS → 运输硬盘 → 中控端 RustFS
```

首期只解决这条链路的完整闭环：**注册硬盘、边缘端导出、硬盘封盘、中控端导入、导入结果查询**。

## 2. 功能清单

### 2.1 中控端

| 编号 | 功能 | 结果 |
|---|---|---|
| C01 | 运输硬盘管理 | 查看文件系统类型；非 ext4 的硬盘经确认后格式化为 ext4；注册、初始化及导入后的重新初始化 |
| C02 | 边缘站点管理 | 维护站点名称、站点编码（中控归档桶名），并为 Edge 分配固定 Key |
| C03 | 封盘运输盘识别 | 读取 `SEALED` 运输盘，显示来源站点、对象数、容量和状态 |
| C04 | 运输盘导入 | 将运输盘对象写入中控 RustFS |
| C05 | 对象去重 | 已成功归档的对象不重复写入 |
| C06 | 导入任务查询 | 展示任务状态、进度、速度、当前对象和错误 |
| C07 | 导入记录 | 查询某块盘、某个 `disk_id` 或某个对象的导入结果 |

### 2.2 边缘端

| 编号 | 功能 | 结果 |
|---|---|---|
| E01 | 站点配置 | 配置站点信息、本地 RustFS 和中控端分配的固定 Key |
| E02 | 可用盘判断 | 判断运输硬盘是否已注册且可用于导出 |
| E03 | 对象扫描 | 通过 S3 接口全量获取本地 RustFS 的对象列表 |
| E04 | 对象导出 | 按硬盘可用容量将对象和对象信息写入运输硬盘 |
| E05 | 封盘 | 当前对象放不下或待导出对象全部完成时，生成不可再修改的对象清单并将 `disk_id` 标记为已封盘 |
| E06 | 导出任务查询 | 展示任务状态、进度、速度、当前对象和错误 |
| E07 | 运行时导出账本 | 记录当前 `disk_id` 的对象写入状态；封盘确认后供下一块硬盘筛选未导出对象 |

### 2.3 两端共有

| 编号 | 功能 | 结果 |
|---|---|---|
| S01 | 本地硬盘挂载与目录扫描 | 两端主程序共用同一套逻辑，自动挂载并扫描本机运输硬盘 |
| S02 | 运输硬盘通讯协议（盘上协议） | 两端使用同一目录结构和文件格式交接数据 |
| S03 | 任务执行 | 创建、执行、失败、恢复导出/导入任务 |
| S04 | WebSocket 页面通讯 | 两端后端向各自前端实时推送硬盘和任务状态 |
| S05 | Docker 一键部署 | 使用单条 Docker Compose 命令启动中控端或边缘端 |

## 3. 架构拆分

系统分为中控端、边缘端和运输硬盘三部分。中控端与边缘端不直接传输对象；运输硬盘是唯一的数据交接介质。

```text
共享 Module
├── 本地硬盘挂载与目录扫描 Module
│   ├── 中控端实例只管理中控主机的运输硬盘
│   └── 边缘端实例只管理边缘主机的运输硬盘
└── WebSocket 页面通讯 Module
    ├── Edge 后端向 Edge 前端推送硬盘和导出任务状态
    └── Center 后端向 Center 前端推送硬盘和导入任务状态

边缘端
├── 管理页面
├── 导出任务 Module
│   ├── 本地 RustFS Module
│   └── 运输盘协议 Module ──→ 运输硬盘
├── 导出账本 Module
└── 边缘端数据库

中控端
├── 管理页面
├── 导入任务 Module
│   ├── 中控 RustFS Module
│   ├── 运输盘协议 Module ←── 运输硬盘
│   └── 对象账本 Module
└── 中控端数据库
```

这里的 Module 是功能归属，而不是先确定代码目录或微服务。每个 Module 对外只暴露完成业务动作所需的 Interface，把设备扫描、文件读写、状态维护等细节留在内部。

## 4. Module 职责与 Interface

### 4.1 本地硬盘挂载与目录扫描 Module

**职责**：由中控端和边缘端主程序共用同一套逻辑，自动将本机新插入的运输硬盘挂载到 `/mnt/rustfs-transfer/{设备名}`，并扫描 `/mnt/rustfs-transfer` 发现、移除硬盘。

**输入**：挂载根目录 `/mnt/rustfs-transfer`、扫描间隔。

**输出**：当前已发现的硬盘列表；硬盘发现、移除和内容变更结果。

**边界**：中控端实例只处理本机插入的硬盘，边缘端实例也只处理本机插入的硬盘；不负责开始导出或导入。

### 4.2 运输硬盘通讯协议 Module

**职责**：读写运输硬盘中的身份信息、`disk_id` 状态、对象清单和对象数据。

**输入**：运输硬盘根目录、硬盘标识、`disk_id`、对象条目。

**输出**：已验证的硬盘信息、`disk_id` 信息、对象条目和校验结果。

**不负责**：扫描 RustFS、决定哪些对象导出、将对象上传到 RustFS。

### 4.3 边缘端导出任务 Module

**职责**：从本地 RustFS 获取对象，将对象写入指定运输硬盘，并完成封盘。

**输入**：站点配置、运输硬盘。

**输出**：已封盘 `disk_id` 及导出任务结果。

**不负责**：中控端导入、运输硬盘注册。

### 4.4 导出账本 Module（边缘端）

**职责**：记录当前 `disk_id` 的对象写入状态；仅在封盘完成后将对象标记为已导出，并为后续运输硬盘筛选尚未导出的对象。

**输入**：对象标识（来源桶、来源对象键、ETag、大小）、`disk_id`、写入结果、封盘结果。

**输出**：待导出对象列表、当前 `disk_id` 运行时记录、已确认的对象导出记录。

**不负责**：对象扫描、对象复制和中控端去重。

### 4.5 中控端导入任务 Module

**职责**：读取 `SEALED` 运输盘，将其中对象归档到中控 RustFS，记录导入结果。

**输入**：运输硬盘、`disk_id`。

**输出**：导入任务结果、归档对象记录。

**不负责**：修改已封盘运输盘中的对象数据、从中控端回传边缘端。

### 4.6 对象账本 Module（中控端）

**职责**：保存对象已归档的事实，供导入任务判断是否需要重复写入。

**输入**：来源 Edge 编码、来源桶、来源对象键、ETag、大小、归档位置。

**输出**：对象是否已归档，以及归档记录。

**不负责**：实际上传对象。

### 4.7 任务与状态 Module

**职责**：保存导出/导入任务、进度和错误，供页面查询和 WebSocket Module 推送。

**输入**：任务创建、进度更新、完成或失败结果。

**输出**：任务详情、任务列表和任务状态。

**不负责**：对象复制和协议文件读写。

### 4.8 WebSocket 页面通讯 Module

**职责**：两端后端程序均通过此 Module 向各自前端页面推送硬盘与任务变化。

**输入**：当前硬盘列表、导出或导入任务状态、页面统计数据。

**输出**：WebSocket 实时事件。

WebSocket 事件、字段和前端处理方式见 [WebSocket前后端通讯协议.md](WebSocket前后端通讯协议.md)。

## 8. Docker 一键部署

首期交付中控端和边缘端各一套 Docker Compose 部署文件。使用者填写对应的环境变量文件后，执行以下命令即可启动：

```bash
docker compose up -d
```

部署文件必须完成以下事项：

- 启动应用及其必需依赖；
- 将宿主机 `/mnt/rustfs-transfer` 挂载目录映射到容器；
- 中控端和边缘端主程序共用本地硬盘自动挂载逻辑，各自只管理所在主机插入的硬盘；容器必须具备挂载硬盘的宿主机权限；
- 中控端还必须具备读取已挂载硬盘文件系统类型、执行 ext4 格式化和重新挂载的宿主机权限；
- 将数据库数据、应用配置和日志映射为持久化目录；
- 通过部署配置提供站点信息、RustFS 连接信息和 Edge 固定 Key；
- 提供中控端与边缘端各自独立的示例环境变量文件。

### 8.1 两端数据库启动初始化

中控端和边缘端主程序启动时，先连接各自数据库，再根据本端数据库设计执行表结构检查：

1. 检查本端所需的数据表、字段、唯一约束和索引是否齐全；
2. 缺少的数据表、字段、唯一约束或索引，由程序按本端数据库模型自动创建；
3. 全部检查和创建成功后，才启动硬盘扫描、导出或导入任务；
4. 已存在字段与模型类型或约束冲突时，程序不删除数据、不重建表，启动失败并明确报出冲突项。

因此，新建空数据库可随 Docker Compose 一键部署自动完成建表；已有数据库只补齐缺少结构，不破坏已有导出、导入和账本数据。
