# Edge 端设计说明

## 1. 职责

Edge 端负责从本地 RustFS 导出对象到运输盘、续写未完成的写盘任务、封盘，以及展示硬盘和导出状态。

数据流：

```text
本地 RustFS → 运输硬盘
```

Edge 不连接 Center；只读取首次部署时配置的站点信息和 Key，只管理插入本机的运输盘。

## 2. 已确定规则

- 通过 S3 接口分页连续扫描本地 RustFS；扫描到未确认导出的对象即写入当前运输盘，不预先加载完整对象列表；
- 对象版本标识为：`source_bucket + source_key + etag + size`；
- 运输盘文件路径和来源存储结构以 [运输硬盘通讯协议.md](运输硬盘通讯协议.md) 为准；
- 导出前后均读取 ETag 和大小；任一变化则删除本次 ZIP 和运行时记录，下一轮重新导出；
- 一块运输盘同一时刻只写一个由 Center 初始化时生成的 `disk_id`；`disk_id` 就是本次运输编号；
- `READY` 盘可开始导出；`WRITING` 盘仅当盘中 `edge.edge_code` 等于本机 Edge 编码时才可继续写；`SEALED` 盘禁止继续写；
- 写盘中断后，使用本机运行时导出账本继续；盘内 ZIP 与账本不一致时，删除多余 ZIP 或无对应 ZIP 的账本记录，再重新导出缺失对象；
- 当前对象放不下或待导出对象已全部写完时封盘；
- 只有封盘成功后，运行时导出账本中的对象才标记为已确认导出；
- 运输盘文件和状态以 [运输硬盘通讯协议.md](运输硬盘通讯协议.md) 为准。

## 3. Module 划分

```text
Edge 主程序
├── 本地硬盘挂载与目录扫描 Module（两端共用）
├── 本地 RustFS Module
├── Edge 配置 Module
├── 导出任务 Module
│   ├── 运输盘协议 Module（两端共用）
│   └── 导出账本 Module
├── 任务与状态 Module（两端共用）
└── WebSocket 页面通讯 Module（两端共用）
```

### 3.1 Edge 配置 Module

**职责**：读取 Edge 站点名称、站点编码、Key 和本地 RustFS S3 连接信息。

**规则**：站点编码和 Key 仅来自首次部署配置；Edge 不向 Center 请求或同步配置。

### 3.2 本地 RustFS Module

**职责**：通过 S3 接口列出对象、读取对象元数据和下载对象内容。

**输出**：来源桶名、来源对象路径、ETag、大小和对象数据流。

### 3.3 导出账本 Module

**职责**：保存当前 `disk_id` 的写盘进度和已确认导出对象。

**规则**：

- 对象 ZIP 成功写入运输盘后，记录为“当前写盘对象”；
- 封盘成功后，当前写盘对象转为“已确认导出”；
- `WRITING` 盘重新插入时，按当前 `disk_id` 的写盘记录恢复；
- 仅按对象版本标识判断是否已经确认导出。

### 3.4 导出任务 Module

**职责**：读取可用运输盘、筛选未确认导出对象、写入 ZIP 并封盘。

**任务状态**：`待导出 → 导出中 → 等待恢复 → 已封盘 / 导出失败`。

**多盘规则**：优先恢复本机 Edge 的 `WRITING` 盘；没有可恢复的 `WRITING` 盘时，扫描到多块 `READY` 运输盘即创建导出任务并记录 `queued_at`，按 `queued_at` 从早到晚逐块导出，同一时间只写一块盘；Edge 重启后继续按该顺序执行。

**失败规则**：硬盘仍挂载时，60 秒后自动按当前 `disk_id` 的运行时账本继续写盘；硬盘被拔出时任务进入 `等待恢复`。

## 4. 导出流程

1. 本地硬盘挂载与目录扫描 Module 发现运输盘。优先恢复本机 Edge 的 `WRITING` 盘；没有可恢复的 `WRITING` 盘时，多块 `READY` 盘同时存在则创建导出任务并记录 `queued_at`，按该时间进入导出队列。
2. 读取 `disk_info.json`：
   - `READY`：等待扫描并确认存在待导出对象；
   - `WRITING`：仅 `edge.edge_code` 与本机 Edge 编码一致时继续；
   - `SEALED`：只展示，不允许导出。
3. 写盘中硬盘被拔出时，任务变为 `等待恢复` 并停止写入；同一 `disk_id` 重新插入后恢复任务。恢复 `WRITING` 盘时，对比盘内 ZIP 和本机当前 `disk_id` 的运行时导出账本：删除盘上多余 ZIP；删除没有对应 ZIP 的账本记录。
4. 选定当前运输盘后，通过 S3 分页连续扫描本地 RustFS；已确认导出对象和当前 `disk_id` 运行时账本中已有的对象均跳过，扫描到其余对象即写入当前盘，不预先加载完整对象列表。
5. 运输盘为 `READY` 且存在待导出对象时，首次写入本机 `edge_name`、`edge_code`、`export_started_at`，状态改为 `WRITING`。恢复 `WRITING` 盘时不得覆盖这些字段，ZIP 密码继续使用原 `export_started_at` 的日期部分。
6. 对每个对象读取来源桶、对象路径、ETag 和大小，计算对象版本标识。
7. 计算可写空间：
   - `free_bytes = 硬盘总容量 - 已使用空间`；
   - `reserve_bytes = free_bytes × 2%`，最低 `2GB`、最高 `8GB`；
   - `writable_bytes = free_bytes - reserve_bytes`；
   - `writable_bytes < 对象大小 + 10MB` 时，停止写入并封盘。
8. 按运输硬盘通讯协议的 ZIP 规则创建对象 ZIP；先写临时文件，完整后改名为 `.zip`。
9. 再次读取对象 ETag 和大小；一致时记录运行时导出账本，不一致时删除本次 ZIP，下一轮重新导出。
10. 当前对象放不下时，封盘当前运输盘：根据运行时导出账本生成 `manifest.jsonl`，使用同一密码写入 `manifest.zip`，计算 SHA256，写入 `edge.export_finished_at`、`edge.manifest_sha256`、`edge.object_count`，最后将 `disk_info.json.state` 更新为 `SEALED`。
11. 封盘成功后，将当前 `disk_id` 的运行时导出对象标记为已确认导出；若仍有下一块 `READY` 盘，继续处理当前尚未写入的对象和后续 S3 页面；没有 `READY` 盘时停止本次扫描。
12. 后续插入新的 `READY` 盘时，从 S3 第一页重新开始扫描；已确认导出对象会被跳过，因此本次扫描停止期间新上传的对象会被发现并导出。
13. S3 扫描到末页时：当前盘已写入对象则封盘；当前盘没有写入对象则删除该盘本次创建的待导出任务，保持 `READY`，不封盘。

对象在扫描后、读取前已被删除时，跳过该对象并继续导出；其他对象读取失败时，任务标记为“导出失败”，60 秒后自动重试。

## 5. 页面

| 页面 | 首期内容 |
|---|---|
| 首页 | 运输盘列表、硬盘卡片、硬盘详情、实时导出记录、已确认导出对象总数和已确认导出数据总量 |
| 导出记录 | 按 `disk_id` 或对象查询已确认导出结果 |

首页通过两端共用的 WebSocket 页面通讯 Module 接收硬盘插拔、硬盘空间和导出任务变化；事件和字段见 [WebSocket前后端通讯协议.md](WebSocket前后端通讯协议.md)。

## 6. 数据库

Edge 数据库用于保存导出任务、运行时导出账本和已确认导出对象；站点配置和 Key 由首次部署配置提供。具体表结构见 [Edge端数据库设计.md](Edge端数据库设计.md)。

## 7. HTTP 接口

导出记录通过 [HTTP前后端接口协议.md](HTTP前后端接口协议.md) 查询；WebSocket 只推送当前硬盘与当前导出任务状态。

## 8. 部署配置

| 配置 | 用途 |
|---|---|
| `database` | Edge 数据库连接信息 |
| `rustfs` | 本地 RustFS S3 连接信息 |
| `edge_name` / `edge_code` / `key` | 首次部署时提供的 Edge 配置 |

公共挂载、扫描和 Docker 配置见 [开发设计说明.md](开发设计说明.md)。
