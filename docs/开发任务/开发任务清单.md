# RustFS 离线运输盘同步系统：开发任务清单

## 1. 目标与原则

按“先锁定交接契约，再完成最小闭环，最后补页面和部署”的顺序开发：

```text
Center 初始化 → Edge 导出并封盘 → Center 导入 → 自动重新初始化
```

运输硬盘协议是 Edge 与 Center 的唯一离线交接契约。协议读写、测试样本和两端实现必须一致，不能由两端各自理解实现。

## 2. 开发前必须确定的事项

以下不是新增功能，而是开始编码前必须选定的实现技术；当前方案设计尚未指定，不能自行假设。

- [ ] T00：确定 Rust 工程结构、后端 Web 框架、前端技术和数据库类型；
- [ ] T01：确定数据库访问方式和表结构检查实现方式；两端启动时按各自模型补齐缺失表、字段、唯一约束和索引；
- [ ] T02：确定 Docker Compose 中应用、数据库、持久化目录及主机磁盘权限的部署方式；
- [ ] T03：准备可格式化的测试运输盘、Edge 测试 RustFS 和 Center 测试 RustFS。

T00 至 T02 未完成前，不开始业务代码，避免因数据库或部署技术更换导致返工。

## 3. 推荐开发顺序

### 阶段 A：工程与公共基础

- [ ] A01：创建工程骨架、配置读取和日志；区分 Edge 与 Center 的部署配置。
- [ ] A02：实现数据库连接与启动表结构检查。
  - Center 模型：`edge_sites`、`disk_ids`、`import_tasks`、`import_objects`；
  - Edge 模型：`export_tasks`、`export_objects`；
  - 空数据库启动后自动建全表结构；已有冲突结构明确报错，不删除数据。
- [ ] A03：实现两端共用的本地硬盘挂载与目录扫描 Module。
  - 自动挂载到 `/mnt/rustfs-transfer/{设备名}`；
  - 每秒扫描，输出完整硬盘列表、文件系统、挂载路径和盘上 `disk_info.json`；
  - 提供 Center 格式化 ext4、重新挂载所需的受控动作。
- [ ] A04：实现两端共用的运输硬盘协议 Module。
  - 读写 `disk_info.json`；
  - 生成和读取对象 ZIP、`manifest.zip`；
  - 执行 ZipCrypto 密码规则、SHA256、路径规则和 `READY / WRITING / SEALED` 状态规则；
  - 只通过 Module Interface 操作盘上文件，业务 Module 不直接拼接路径或修改 JSON。
- [ ] A05：为 A03、A04 建立自动化测试；准备 `READY`、`WRITING`、`SEALED` 三种固定测试盘样本。

**阶段完成条件**：空数据库可启动；可识别运输盘；Center 能初始化出 `READY` 盘；协议 Module 能读写并校验测试盘。

### 阶段 B：Center 最小闭环

- [ ] B01：实现 Edge 站点注册与查询；注册后不提供修改操作。
- [ ] B02：实现 Center 运输盘初始化与重新初始化。
  - 非 ext4：确认后格式化、挂载、生成新 `disk_id`、登记为 `FREE`；
  - ext4 但未初始化：清理盘内内容、生成新 `disk_id`、登记为 `FREE`。
- [ ] B03：实现 Center RustFS Module：创建或复用 `edge_code` 桶、写入 `source_bucket/source_key`。
- [ ] B04：实现对象账本、导入队列和导入任务恢复。
  - 仅 `SEALED` 且 `disk_id = FREE` 的盘入队；
  - 多盘按 `queued_at` 串行导入；
  - 成功对象写入 `import_objects`，已归档对象计入进度但跳过写入。
- [ ] B05：实现导入执行器：校验清单 SHA256、流式读取清单、解压对象、校验 SHA256、写入 RustFS、成功后标记 `USED` 并自动重新初始化。
- [ ] B06：实现 Center HTTP：站点注册/查询、格式化并初始化、初始化并注册、导入记录查询。

**阶段完成条件**：使用预制的 `SEALED` 测试盘可完成导入，归档目录与清单一致；全部对象成功后盘被重新初始化。

### 阶段 C：Edge 最小闭环

- [ ] C01：实现 Edge 配置 Module：站点名称、站点编码、Key 与本地 RustFS S3 连接信息均从部署配置读取。
- [ ] C02：实现 Edge RustFS Module：分页列举桶和对象、读取元数据、流式下载对象。
- [ ] C03：实现导出账本与导出队列。
  - 记录 `WRITTEN` 与 `CONFIRMED`；
  - 优先恢复本机的 `WRITING` 盘；其余 `READY` 盘按 `queued_at` 串行处理；
  - 支持盘与账本对账后恢复。
- [ ] C04：实现导出执行器。
  - 扫描时按对象版本标识跳过 `CONFIRMED` 和当前盘 `WRITTEN`；
  - 按预留空间规则写入对象 ZIP、复核 ETag 和大小；
  - 写满或导出完成后生成 `manifest.zip`、写入封盘信息并最后变更为 `SEALED`；
  - 拔盘进入“等待恢复”，其他读取失败 60 秒后自动重试。
- [ ] C05：实现 Edge HTTP：导出记录查询。

**阶段完成条件**：Center 初始化的 `READY` 盘插入 Edge 后，可自动写盘并封盘；生成的 `SEALED` 盘可被阶段 B 的 Center 成功导入。

### 阶段 D：页面与实时通讯

- [ ] D01：实现公共 WebSocket Module：`GET /ws`、连接/重连 `snapshot`、完整 `disks_updated` 列表及每秒任务进度推送。
- [ ] D02：实现 Edge 页面：首页硬盘列表、详情、导出实时进度、确认导出总数/总数据量、导出记录页。
- [ ] D03：实现 Center 页面：首页硬盘列表、详情、导入实时进度、导入总数/总数据量、导入记录页、站点管理页。
- [ ] D04：接入 HTTP 操作与 WebSocket 事件；前端按完整 `disks_updated` 列表更新卡片，避免插拔多盘时残留旧卡片。

**阶段完成条件**：插拔硬盘、空间变化、当前文件进度、速度、预计完成时间和统计变化均能实时展示；历史记录通过 HTTP 分页查询。

### 阶段 E：部署与验收

- [ ] E01：提供 Edge 与 Center 各自 Docker Compose、示例环境变量和持久化目录配置。
- [ ] E02：验证容器具有扫描、挂载、Center 格式化和重新挂载所需的 Linux 主机权限。
- [ ] E03：编写端到端验收脚本：初始化 → 导出 → 封盘 → 导入 → 重新初始化。
- [ ] E04：覆盖异常验收：拔盘恢复、Edge/Center 重启恢复、对象已删除跳过、导入失败后 60 秒重试、多盘排队。

## 4. 可并行开发安排

| 并行组 | 可同时进行的任务 | 前置条件 | 合并点 |
|---|---|---|---|
| P1 | A01 工程配置、A02 数据库检查、A03 硬盘挂载扫描、A04 协议 Module | T00 技术选型完成 | A05 公共测试盘和协议测试通过 |
| P2 | B01/B02 Center 站点与初始化、C01/C02 Edge 配置与 RustFS 读取 | A01、A02、A03 已具备 | 可由同一 `READY` 测试盘联调 |
| P3 | B03/B04/B05 Center 导入链路、C03/C04 Edge 导出链路 | A04 协议 Module 与测试盘已锁定 | Edge 封盘产物可被 Center 导入 |
| P4 | D02/D03 前端页面骨架、D01 WebSocket 后端 | HTTP/WS 字段已定，可用静态样本先开发 | 对接真实任务与硬盘事件 |
| P5 | E01 Docker 部署、E03/E04 自动化验收 | 两端最小闭环完成 | Linux 实机端到端验收 |

**不能并行的关键点**：A04 协议 Module 的盘上文件格式和测试样本必须先固定；Edge 写盘与 Center 读盘只能基于同一份样本实现和验收。

## 5. 当前方案设计审查结果

已发现并处理的文档矛盾：

- Center 页面原先写“编辑 Edge 站点”，但站点注册后不允许修改任何信息；现已改为只新增和查看；
- Edge 文档仍写“WebSocket 后续补充”，但公共 WebSocket 协议已存在；现已改为引用该协议。

仍需在 T00 中确定、否则不能开始实现的事项：数据库类型、Rust 后端框架、前端技术与部署目录。其余业务规则、盘上协议、两端数据库模型、HTTP 和 WebSocket 通讯已经可以进入开发。
