# RustFS 离线运输盘同步系统：开发任务清单

## 1. 目标与原则

按“先锁定交接契约，再完成最小闭环，最后补页面和部署”的顺序开发：

```text
Center 初始化 → Edge 导出并封盘 → Center 导入 → 自动重新初始化
```

运输硬盘协议是 Edge 与 Center 的唯一离线交接契约。协议读写、测试样本和两端实现必须一致，不能由两端各自理解实现。

## 2. 开发前基础任务

技术栈、目录和本机运行方式已分别由 [技术选型.md](技术选型.md) 和 [本机开发环境规划.md](本机开发环境规划.md) 固定。本节只列出开始业务开发前需要完成的基础任务。

- [ ] T00：按 [技术选型.md](技术选型.md) 创建 Rust 工程结构、Axum 后端、SQLite 数据库，并精简 Vben `web-antd` 前端；
- [ ] T01：建立 `database/edge/`、`database/center/` 的版本化建表 SQL，并使用 SQLx 实现 SQLite 表结构检查；两端启动时按各自 SQL 与模型补齐缺失表、字段和索引；唯一性通过唯一索引实现；
- [ ] T02：按 [技术选型.md](技术选型.md) 提供 Docker Compose、SQLite 持久化目录及主机磁盘权限配置；
- [ ] T03：准备可格式化的测试运输盘、Edge 测试 RustFS 和 Center 测试 RustFS。
- [ ] T04：按 [本机开发环境规划.md](本机开发环境规划.md) 创建目录、配置模板、Linux 本机一键启动脚本和 Makefile 命令。

T00 至 T04 全部完成后，才开始业务代码。

## 3. 推荐开发顺序

### 阶段 A：工程与公共基础

- [ ] A01：创建工程骨架、配置读取和日志；区分 Edge 与 Center 的部署配置。
- [ ] A02：实现数据库连接与启动表结构检查。
  - Center 模型：`edge_sites`、`disk_ids`、`import_tasks`、`import_objects`；
  - Edge 模型：`export_tasks`、`export_objects`；
  - 空数据库启动后自动建全表结构；已有冲突结构明确报错，不删除数据。
- [ ] A03：实现两端共用的本地硬盘挂载与目录扫描 Module。
  - 自动挂载到 `/mnt/rustfs-transfer/{设备名}`；
  - 每秒扫描，输出完整硬盘列表、文件系统、挂载路径和盘上 `disk_info.json`；
  - 提供 Center 格式化 ext4、重新挂载所需的受控动作。
- [ ] A04：实现两端共用的运输硬盘协议 Module。
  - 读写 `disk_info.json`；
  - 生成和读取对象 ZIP、`manifest.zip`；
  - 执行 ZipCrypto 密码规则、SHA256、路径规则和 `READY / WRITING / SEALED` 状态规则；
  - 只通过 Module Interface 操作盘上文件，业务 Module 不直接拼接路径或修改 JSON。
- [ ] A05：为 A03、A04 建立自动化测试；准备 `READY`、`WRITING`、`SEALED` 三种固定测试盘样本。
- [ ] A06：按 T02 的 Docker Compose 对测试硬盘或磁盘镜像完成最小权限验证：容器可识别、挂载、Center 格式化 ext4 并重新挂载；不得使用业务硬盘。

**阶段完成条件**：空数据库可启动；可识别运输盘；协议 Module 能读写并校验测试盘；Docker 已在测试设备上通过最小硬盘权限验证。

### 阶段 B：Center 站点与运输盘初始化

- [ ] B01：实现 Edge 站点注册与查询；注册后不提供修改操作。
- [ ] B02：实现 Center 运输盘初始化与重新初始化。
  - 非 ext4：确认后格式化、挂载、生成新 `disk_id`、登记为 `FREE`；
  - ext4 但未初始化：清理盘内内容、生成新 `disk_id`、登记为 `FREE`。
**阶段完成条件**：Center 可注册测试 Edge 并初始化出 `READY` 运输盘；将相同站点名称、编码和 Key 写入 Edge 本机配置。

### 阶段 C：Edge 最小闭环

- [ ] C01：实现 Edge 配置 Module：站点名称、站点编码、Key 与本地 RustFS S3 连接信息均从部署配置读取。
- [ ] C02：实现 Edge RustFS Module：分页列举桶和对象、读取元数据、流式下载对象。
- [ ] C03：实现导出账本与导出队列。
  - 记录 `WRITTEN` 与 `CONFIRMED`；
  - 优先恢复本机的 `WRITING` 盘；其余 `READY` 盘按 `queued_at` 串行处理；
  - 支持盘与账本对账后恢复。
- [ ] C04：实现导出执行器。
  - S3 分页扫描时按对象版本标识跳过 `CONFIRMED` 和当前盘 `WRITTEN`，扫描到对象即写入当前盘，不预先加载完整对象列表；
  - 按预留空间规则写入对象 ZIP、复核 ETag 和大小；
  - 当前盘写满后生成 `manifest.zip`、写入封盘信息并最后变更为 `SEALED`；有下一块 `READY` 盘则继续当前扫描，没有可用盘则停止本次扫描；后续新盘插入时从 S3 第一页重新扫描；
  - 拔盘进入“等待恢复”，其他读取失败 60 秒后自动重试。
- [ ] C05：实现 Edge HTTP：导出记录查询。

**阶段完成条件**：Center 初始化的 `READY` 盘插入 Edge 后，可自动写盘并封盘；生成的 `SEALED` 盘作为阶段 D 的导入输入。

### 阶段 D：Center 导入闭环（Center 任务 B03-B07）

- [ ] B03：实现 Center RustFS Module：创建或复用 `edge_code` 桶、写入 `source_bucket/source_key`。
- [ ] B04：实现对象账本、导入队列和导入任务恢复。
  - 仅 `SEALED` 且 `disk_id = FREE` 的盘入队；
  - 多盘按 `queued_at` 串行导入；
  - 成功对象写入 `import_objects`，已归档对象计入进度但跳过写入。
- [ ] B05：实现导入执行器：校验清单 SHA256、流式读取清单、解压对象、校验 SHA256、写入 RustFS、成功后标记 `USED` 并自动重新初始化。
- [ ] B06：实现 Center HTTP：站点注册/查询、格式化并初始化、初始化并注册、导入记录查询。
- [ ] B07：建立 Edge → Center 协议兼容测试：由 C04 真实生成 `SEALED` 测试盘，Center 读取该盘并校验 `manifest.zip`、对象 ZIP、SHA256 和归档路径。

**阶段完成条件**：使用 C04 生成的 `SEALED` 测试盘可完成导入，归档目录与清单一致；全部对象成功后盘被重新初始化；B07 自动化兼容测试通过。

### 阶段 E：页面与实时通讯（前端任务 D01-D04）

- [ ] D01：实现公共 WebSocket Module：`GET /ws`、连接/重连 `snapshot`、完整 `disks_updated` 列表及每秒任务进度推送。
- [ ] D02：基于 Vben `web-antd` 实现 Edge 页面：首页硬盘列表、详情、导出实时进度、确认导出总数/总数据量、导出记录页。
- [ ] D03：基于 Vben `web-antd` 实现 Center 页面：首页硬盘列表、详情、导入实时进度、导入总数/总数据量、导入记录页、站点管理页。
- [ ] D04：接入 HTTP 操作与 WebSocket 事件；前端按完整 `disks_updated` 列表更新卡片，避免插拔多盘时残留旧卡片。

**阶段完成条件**：插拔硬盘、空间变化、当前文件进度、速度、预计完成时间和统计变化均能实时展示；历史记录通过 HTTP 分页查询。

### 阶段 F：部署与验收（部署任务 E01-E04）

- [ ] E01：按 [技术选型.md](技术选型.md) 与 [本机开发环境规划.md](本机开发环境规划.md) 提供 Edge 与 Center 的 Dockerfile、Docker Compose、示例环境变量、持久化目录配置和 `make image-*` 镜像构建命令。
- [ ] E02：在完整 Edge 与 Center Docker Compose 部署中复验容器的扫描、挂载、Center 格式化和重新挂载权限。
- [ ] E03：编写端到端验收脚本：初始化 → 导出 → 封盘 → 导入 → 重新初始化。
- [ ] E04：覆盖异常验收：拔盘恢复、Edge/Center 重启恢复、对象已删除跳过、导入失败后 60 秒重试、多盘排队。

## 4. 开发依赖顺序

```text
T00 → T01 → T02 → T03 → T04
        ↓
A01 → A02 → A03 → A04 → A05
        ↓
A06
        ↓
B01 → B02（Center 初始化 READY 盘）
        ↓
C01 → C02 → C03 → C04 → C05（Edge 导出并封盘）
        ↓
B03 → B04 → B05 → B06 → B07（Center 导入并验证协议兼容）
        ↓
D01 → D02 → D03 → D04（实时通讯与页面）
        ↓
E01 → E02 → E03 → E04（完整 Docker 部署与验收）
```

公共基础、运输盘初始化、Edge 导出、Center 导入必须按此顺序完成；不并行拆分业务流程。

## 5. 开发日志

每个实际开发或测试日期，在 `log/` 下创建一个 `YYYY-MM-DD.md` 文件，例如 `log/2026-08-21.md`。同一天持续追加到同一文件，不创建空日志。

每次记录包含：

- 完成的任务编号和功能；
- 修改的主要文件；
- 执行的测试或检查及结果；
- 已知问题；
- 下一步。
