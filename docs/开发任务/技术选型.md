# RustFS 离线运输盘同步系统：技术选型

## 1. 选型目标

首期目标是两端在 Linux 上独立部署、通过 Docker Compose 一键启动，并稳定执行本机硬盘操作、大文件流式导出/导入和页面实时展示。

因此选择单体程序与本机 SQLite，不拆分微服务，不增加独立消息队列或缓存服务。

## 2. 推荐技术栈

| 范围 | 选型 | 用途 |
|---|---|---|
| 运行环境 | Linux | Edge 与 Center 的部署和硬盘操作环境 |
| 后端语言 | Rust（稳定版，Edition 2024） | 硬盘操作、S3 流式传输、ZIP、任务执行、HTTP 和 WebSocket |
| 异步运行时 | Tokio | S3 流、HTTP、WebSocket 和后台任务 |
| 后端框架 | Axum | HTTP 接口、WebSocket、静态前端文件服务 |
| 数据库 | SQLite | Edge 导出账本与 Center 导入账本；每端各自一个本机数据库文件 |
| 数据库访问 | SQLx（SQLite） | 数据查询、事务、启动迁移与表结构检查 |
| 建表 SQL | `database/edge/`、`database/center/` | 两端版本化建表与后续表结构变更 |
| 对象存储访问 | `aws-sdk-s3` | 通过 RustFS 的 S3 兼容接口列举、读取和写入对象 |
| ZIP | Rust `zip` crate | 创建和读取对象 ZIP、`manifest.zip`，使用 ZipCrypto |
| 校验 | `sha2` crate | 计算对象与 `manifest.zip` 的 SHA256 |
| 配置与序列化 | `serde`、`serde_json`、环境变量文件 | `disk_info.json`、清单、HTTP/WS JSON、部署配置 |
| 日志 | `tracing`、`tracing-subscriber` | 任务、硬盘、S3、导入导出与错误日志 |
| 前端管理框架 | Vben Admin 5 | Edge 与 Center 管理页面的布局、菜单、路由、表格和通用后台能力 |
| 前端应用 | Vben `web-antd` | 选择 Vben 内置的 Ant Design Vue 应用 |
| 前端基础能力 | Vue 3 + TypeScript + Vite + Ant Design Vue + Pinia | 由 Vben Admin 提供和统一维护，不从零重复搭建 |
| 前端通讯 | Vben 内置请求能力 + 原生 WebSocket | HTTP 历史查询和操作；实时硬盘、任务与统计推送 |
| 前端包管理与构建 | pnpm + Vben 工作区工具链 | 锁定、安装和构建前端依赖 |
| 部署 | Docker + Docker Compose | Edge、Center 一键部署与持久化目录映射 |

## 3. 后端部署形态

每个 Edge 或 Center 都是一个 Rust 程序。该程序同时提供：

- 后台硬盘扫描、导出或导入任务；
- HTTP 接口；
- WebSocket `GET /ws`；
- Vben `web-antd` 构建后的静态文件。

生产部署不单独启动前端容器、WebSocket 服务或任务服务。

```text
Docker Compose
└── app 容器
    ├── Rust 后端程序
    ├── Vben `web-antd` 构建后的静态文件
    ├── HTTP / WebSocket
    ├── 导出或导入任务
    └── SQLite 数据库文件（映射到宿主机持久化目录）
```

Edge 使用 `/data/edge.db`；Center 使用 `/data/center.db`。数据库文件只由本机应用容器访问，不放到 NFS、共享盘或其他网络文件系统。

## 4. SQLite 规则

- Edge 与 Center 各自使用独立 SQLite 数据库文件；
- 启动时开启 WAL 模式，并设置数据库忙等待时间；
- 每端只运行一个应用实例，任务按既定顺序执行；
- 应用启动时按本端 `database/` 目录的 SQL 检查并创建表，再按数据库设计检查字段和索引；唯一性由唯一索引实现；缺失结构自动补齐，冲突结构报错停止启动；
- Docker 必须映射 `/data` 为持久化目录，不能随容器删除。

当前不使用 PostgreSQL。只有未来需要多台应用服务器共同读写同一数据库时，才评估迁移到 PostgreSQL。

## 5. Linux 硬盘操作

硬盘操作封装在两端共用的本地硬盘挂载与目录扫描 Module 内，对导出、导入 Module 只暴露硬盘列表和受控动作。

该 Module 在 Linux 上调用系统能力完成：

- 读取块设备与文件系统信息；
- 挂载到 `/mnt/rustfs-transfer/{设备名}`；
- Center 格式化 ext4、重新挂载；
- 扫描挂载目录并读取盘上协议文件。

Docker 部署时，应用容器必须具备相应的宿主机设备、挂载和 Center 格式化权限；开发阶段先在 Linux 主机直接运行 Rust 程序调试该 Module，最终再验证 Docker 权限。

## 6. 前端规则

- 以 Vben Admin 5 的 `web-antd` 作为唯一前端基础，Edge 与 Center 共享该基础但分别构建各自页面；
- 前端首次加载及 WebSocket 重连时使用 `snapshot` 初始化；
- 硬盘列表只依据完整的 `disks_updated` 刷新；
- 历史记录、站点注册、格式化和初始化通过 HTTP；实时硬盘、进度和统计只通过 WebSocket；
- 前端生产构建物由 Axum 提供，HTTP 与 WebSocket 共用一个域名和端口。

### 6.1 Vben 精简方式

Vben 5 不提供独立的精简仓库或分支。前端初始化时采用 Vben 主仓库中的 `apps/web-antd`，然后：

1. 删除其他 UI 应用，只保留 `apps/web-antd`；
2. 删除不使用的 `playground`、文档和 Mock 服务；
3. 删除演示路由、演示页面与不需要的通用组件；
4. 保留并开发本项目路由：Edge 首页、Edge 导出记录、Center 首页、Center 导入记录、Center Edge 站点管理；
5. 调整根目录脚本，只保留 `web-antd` 的开发、构建、类型检查和测试命令。

不从零创建 Vue 管理后台，也不再单独选择 Axios、Pinia、Ant Design Vue 等前端基础库。
