# RustFS 离线运输盘同步系统：本机开发环境规划

## 1. 适用范围

本规划适用于 Linux 开发机。本机开发时，Rust 后端直接运行，Vben 前端通过开发服务器运行；最终部署才使用 Docker Compose 启动完整 Edge 或 Center。

## 2. 项目目录结构

```text
RustFSDisk/
├── Cargo.toml                         # Rust 工作区
├── crates/
│   ├── transport-protocol/             # disk_info、ZIP、manifest 协议 Module
│   ├── disk-runtime/                   # Linux 硬盘挂载、扫描、格式化 Module
│   ├── persistence/                    # SQLite、迁移、表结构检查 Module
│   └── app-core/                       # 任务、S3、WebSocket 等共用业务 Module
├── apps/
│   ├── edge/                           # Edge Rust 程序
│   └── center/                         # Center Rust 程序
├── frontend/                           # 精简后的 Vben Admin 工作区
│   └── apps/
│       └── web-antd/                   # 唯一保留的前端应用
├── config/
│   ├── edge/
│   │   ├── .env.example                # Edge 后端本机配置模板
│   │   └── .env                        # 本机实际配置，不提交 Git
│   └── center/
│       ├── .env.example                # Center 后端本机配置模板
│       └── .env                        # 本机实际配置，不提交 Git
├── database/                            # SQLite 表结构 SQL，只提交建表脚本
│   ├── edge/
│   │   └── 001_init.sql                 # Edge：export_tasks、export_objects
│   └── center/
│       └── 001_init.sql                 # Center：edge_sites、disk_ids、import_tasks、import_objects
├── deploy/
│   ├── edge/                           # Edge Docker Compose 与配置模板
│   ├── center/                         # Center Docker Compose 与配置模板
│   └── dev/                            # 本机测试 RustFS 等开发依赖
├── scripts/
│   ├── dev-edge.sh                     # 启动 Edge 后端与前端
│   ├── dev-center.sh                   # 启动 Center 后端与前端
│   ├── stop-dev.sh                     # 停止本机开发服务
│   ├── check.sh                        # 后端和前端检查
│   └── infra.sh                        # 启停本机测试 RustFS
├── runtime/                            # 本机运行数据，不提交 Git
│   ├── edge/
│   │   ├── edge.db                      # Edge SQLite 数据库文件
│   │   ├── backend.log                  # Edge 后端运行日志
│   │   └── frontend.log                 # Edge 前端开发日志
│   └── center/
│       ├── center.db                    # Center SQLite 数据库文件
│       ├── backend.log                  # Center 后端运行日志
│       └── frontend.log                 # Center 前端开发日志
├── docs/
└── Makefile                            # 统一开发命令入口
```

目录职责固定：盘上协议只能在 `transport-protocol` 实现；Linux 硬盘操作只能在 `disk-runtime` 实现；Edge、Center 不直接执行挂载命令或直接拼接盘上文件路径。

## 3. 本机配置文件

### 3.1 Edge 后端

模板：`config/edge/.env.example`；实际文件：`config/edge/.env`。

```dotenv
APP_SIDE=EDGE
HTTP_ADDR=127.0.0.1:8081
DATABASE_URL=sqlite:///绝对路径/runtime/edge/edge.db
MOUNT_ROOT=/mnt/rustfs-transfer
SCAN_INTERVAL_SECONDS=1
RUSTFS_ENDPOINT=http://127.0.0.1:9000
RUSTFS_ACCESS_KEY=填写本机测试访问密钥
RUSTFS_SECRET_KEY=填写本机测试访问密钥
EDGE_NAME=填写站点名称
EDGE_CODE=填写站点编码
EDGE_KEY=填写中控分配的Key
```

### 3.2 Center 后端

模板：`config/center/.env.example`；实际文件：`config/center/.env`。

```dotenv
APP_SIDE=CENTER
HTTP_ADDR=127.0.0.1:8082
DATABASE_URL=sqlite:///绝对路径/runtime/center/center.db
MOUNT_ROOT=/mnt/rustfs-transfer
SCAN_INTERVAL_SECONDS=1
RUSTFS_ENDPOINT=http://127.0.0.1:9001
RUSTFS_ACCESS_KEY=填写本机测试访问密钥
RUSTFS_SECRET_KEY=填写本机测试访问密钥
```

### 3.3 Vben 前端

前端使用 Vite Mode 区分 Edge 与 Center，不创建两套前端工程：

```text
frontend/apps/web-antd/.env.edge.example
frontend/apps/web-antd/.env.center.example
```

Edge 示例：

```dotenv
VITE_APP_SIDE=EDGE
VITE_API_BASE_URL=http://127.0.0.1:8081
VITE_WS_URL=ws://127.0.0.1:8081/ws
```

Center 示例：

```dotenv
VITE_APP_SIDE=CENTER
VITE_API_BASE_URL=http://127.0.0.1:8082
VITE_WS_URL=ws://127.0.0.1:8082/ws
```

实际 `.env`、数据库文件、日志、PID 和测试访问密钥均不得提交 Git；只提交 `.env.example`。

## 4. 数据库与建表 SQL

数据库文件和建表 SQL 分开管理：

- `runtime/edge/edge.db`、`runtime/center/center.db` 是实际运行数据，不能提交 Git；
- `database/edge/001_init.sql`、`database/center/001_init.sql` 是可审查、可提交 Git 的表结构来源；
- Edge 启动时只读取并执行 `database/edge/` 下的 SQL；Center 只读取并执行 `database/center/` 下的 SQL；
- 程序先检查已有数据库的表、字段和索引；唯一性由唯一索引实现。缺失时执行相应 SQL 补齐，冲突时停止启动并输出错误；不删除已有数据。

后续表结构变更按递增编号新增 SQL，例如 `002_add_xxx.sql`，不修改已经发布的 `001_init.sql`。

## 5. 本机一键启动脚本

### 5.1 `scripts/dev-edge.sh`

执行顺序：

1. 检查 `config/edge/.env` 是否存在；
2. 创建 `runtime/edge/`；
3. 启动 Edge Rust 后端，日志写入 `runtime/edge/backend.log`，PID 写入 `runtime/edge/backend.pid`；
4. 使用 Vite 的 `edge` Mode 启动 `web-antd`，日志写入 `runtime/edge/frontend.log`，PID 写入 `runtime/edge/frontend.pid`；
5. 前端进程结束或收到 Ctrl+C 时，脚本自动停止同一次启动的 Edge 后端。

### 5.2 `scripts/dev-center.sh`

与 Edge 脚本相同，但读取 `config/center/.env`，使用 `center` Mode、Center 端口与 `runtime/center/`。

### 5.3 `scripts/stop-dev.sh`

读取 `runtime/edge/*.pid` 和 `runtime/center/*.pid`，停止仍在运行的本机后端与前端进程，并清理 PID 文件。不删除 SQLite 数据库、日志和运输盘测试文件。

### 5.4 `scripts/infra.sh`

管理 `deploy/dev/` 中的本机测试 RustFS。支持：

```bash
./scripts/infra.sh up
./scripts/infra.sh down
```

本机开发依赖只启动测试 RustFS；SQLite 由 Rust 程序直接创建，不启动数据库容器。

## 6. 统一命令

`Makefile` 只封装脚本，不复制业务逻辑：

```bash
make infra-up      # 启动测试 RustFS
make infra-down    # 停止测试 RustFS
make dev-edge      # 启动 Edge 后端 + Vben 前端
make dev-center    # 启动 Center 后端 + Vben 前端
make stop          # 停止本机前后端服务
make check         # cargo fmt、clippy、cargo test、前端类型检查
make logs-edge     # 持续查看 Edge 后端日志
make logs-center   # 持续查看 Center 后端日志
make image-edge    # 一键构建 Edge Docker 镜像
make image-center  # 一键构建 Center Docker 镜像
make image-all     # 一键构建 Edge 与 Center Docker 镜像
```

不提供 `make dev-all`。Edge 与 Center 使用同一块运输盘时应按真实运输流程先后启动和测试，避免在同一挂载目录中同时操作同一块盘。

`image-edge` 和 `image-center` 都从同一套 `frontend/apps/web-antd/` 源码构建：前者使用 `edge` Mode，后者使用 `center` Mode；最终分别打包进各自镜像。

## 7. 开发与部署的边界

| 场景 | 运行方式 |
|---|---|
| 日常后端与前端开发 | `make dev-edge` 或 `make dev-center` |
| 测试 RustFS | `make infra-up` |
| 协议、封盘、导入测试 | Linux ext4 测试磁盘镜像或专用测试硬盘 |
| Docker 权限与一键部署验收 | `deploy/edge/` 或 `deploy/center/` 的 Docker Compose |

开发阶段不格式化真实业务硬盘；格式化功能只对测试磁盘镜像或专用测试硬盘验证。
