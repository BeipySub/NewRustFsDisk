# 离线运输盘封盘与一致性导入专利技术交底书

## 1. 发明名称

一种离线运输盘封盘与一致性导入方法、系统、设备及存储介质。

## 2. 要解决的问题

边缘站点与中控站点网络不连通时，需要通过可移动硬盘传送大量对象文件。普通复制方式无法明确判断硬盘中的文件是否完整，也无法防止未写完的数据被中控导入。

## 3. 方案说明

系统由 Edge、运输硬盘和 Center 组成。中控初始化运输盘时生成一次性的 `disk_id`，并将盘状态设为 `READY`。

Edge 写入对象时，将盘状态更新为 `WRITING`。每个对象先写为临时 ZIP 文件，写完后原子改名为正式 ZIP 文件；对象写入成功并复核来源对象的 ETag 和大小未变化后，才写入 Edge 运行时账本。

Edge 同时根据硬盘剩余空间计算可写空间并预留安全空间。当前对象无法完整写入时，Edge 封盘当前运输盘；有下一块 `READY` 盘时，继续导出尚未确认导出的对象。对象版本由来源桶名、来源对象键、ETag 和大小组成，已封盘确认的对象版本不重复导出。

全部对象写完或剩余空间不足时，Edge 根据运行时账本生成加密 `manifest.zip`，计算其 SHA256，并写入对象数量、封盘时间和清单校验值。最后才把运输盘状态更新为 `SEALED`。

Center 只处理 `SEALED` 的运输盘。Center 校验 `disk_id` 尚未使用、来源站点已注册、清单 SHA256 正确后，逐条读取清单并导入对象。对每个对象，Center 先以 Edge 编码、来源桶名、来源对象键、ETag 和大小查询对象账本；已归档对象跳过写入，未归档对象在 SHA256 校验并写入对象存储后新增账本记录。全部对象成功后，Center 将旧 `disk_id` 标记为 `USED`，再重新初始化硬盘并生成新的 `disk_id`。

## 4. 关键技术特征

1. 用一次性 `disk_id` 表示一次离线运输，不以物理硬盘序列号作为运输身份。
2. 运输盘采用 `READY`、`WRITING`、`SEALED` 状态控制；`SEALED` 只在清单、校验值和封盘信息均完成后最后写入。
3. 对象先写临时文件，写完后再原子改名；账本只记录已完整写入且复核通过的对象。
4. Center 仅导入已封盘运输盘，并在全部对象成功后才使该运输编号失效和重新初始化硬盘。
5. 依据运输盘可写空间决定自动封盘，并在下一块运输盘上继续处理未确认导出的对象。
6. 依据对象版本账本跳过已归档对象；未归档对象校验并写入成功后才新增账本记录。

## 5. 技术效果

- 避免中控把写入中、写入不完整或清单不完整的运输盘当作可导入数据。
- 在断电、拔盘或任务失败后，运输盘状态仍可作为导入边界。
- 每次运输均可追溯，且同一运输编号不会被重复使用。

## 6. 可选实施方式

- 对象包可采用 ZIP 或其他压缩/封装格式。
- 清单可采用 JSONL、数据库导出文件或其他逐条读取的结构。
- 完整性校验可采用 SHA256 或其他摘要算法。
